01

现在的 AI 助手，都卡在最后一公里

能聊、能写、能改代码的产品很多。但「改完之后你敢不敢让它落到磁盘上」，才是日常真正卡住的地方。

CLOUD AGENT

能力最强，数据先出门

代码、文档、密钥都要先上传到服务商。对涉密、内网、合规敏感的场景，这一步就已经出局。

OPEN-SOURCE CLIENT

界面成熟，但大多只能聊

能连模型、能存历史，却停在「给你一段文本」。真能改文件的，又被绑死在某个 IDE 或某种语言里。

WORKFLOW PLATFORM

能编排，但要一台服务器

要部署、要数据库、要运维，还要固定成一张流程图。个人和小团队的日常任务根本撑不起这套成本。

别人卖的是「AI 能改多少」。
这个项目卖的是：你敢签多少。

所以它不只做了「执行」，还做了「交付」：块级接受、合成结果跑门禁、机械推导的交付摘要、未验证清单、可撤销的写回。这些不是一个功能点，是一条链路。

    04

    把 Token 账单，做成可测量的工程

    system 与 tools 逐轮字节稳定，用 FNV-1a 指纹覆盖完整规格侦测前缀漂移；主会话与子代理各走独立缓存线；命中率与折算节省实时可见。

    对话轮数60 轮
    每轮前缀（system + tools）6000 tokens
    36.0万累计前缀 tokens
    100%缓存命中率
    ¥0.00折算节省

    口径：命中价按未命中价的 10% 计（DeepSeek 风格），示例单价 ¥15 / 百万 input tokens。 换成你自己的服务商价目，直接按比例换算即可。第一轮总是未命中，这里忽略不计。

    未做缓存
    36.0万
    本项目
    3.6万

    为什么难：多数客户端每轮都在 system 里拼时间戳、随机 id 或漂移的工具顺序，缓存从一开始就失效。 要命中，就得让整个应用的状态变更都受控：压缩上下文仍保留前缀、注册/启停工具走显式失效、发送前剔除内部字段。

    刷新、崩溃后按事件顺序 fold 还原；磁盘有日志时以日志为事实源，覆盖 localStorage。

    fork

    从任意历史会话复制前缀开新分支，保留 model.request 锚点，随时分叉试错。

    崩溃恢复

    逐行解析，损坏或半截的行自动跳过，不会因为一行坏掉丢整段历史。

    降级

    纯浏览器直开（无 messagesAPI）时自动 no-op，行为与从前一致。

    06

    不改源码，也能把它变成你的工具

    三条扩展路径都做成了「零侵入」：新工具进入既有工具循环，新方法论进入 system 前缀，新知识进本地库。

    可插拔工具

    面板零代码注册，或脚本 window.registerTool；被映射成一个内置 MCP Server，多轮循环、轨迹回放、子代理全部直接可用。

    window.registerTool({
  name: 'my_tool',
  description: '…',
  inputSchema: { type:'object' },
  handler: async (args) => ({ ok: true })
});
// 注册即 invalidateTools()：只付一次 cache miss

    08

    它在哪里会撑不住

    把边界写清楚，比把优点写十遍更有用。下面这些是读代码就能验证的事实，不是谦虚话。

    架构债高

    零构建、经典 <script> 顺序加载、模块共享全局作用域。单人可维护，多人协作与长期演进成本高。

    首包体积中

    静态资源约 35MB（多个 WASM、字体、编辑器）。「可离线」的代价，首屏与移动端体验受限。

    沙箱边界高

    浏览器内 Node 沙箱不等于系统级隔离。不执行不可信代码；多人部署需自备服务端代理与访问控制。

    规模上限中

    IndexedDB 存储 + 前端向量检索。万级文档、超大仓库仍不如服务端 RAG 与专用索引。

    许可与文档中

    计划 Apache-2.0，但 LICENSE 文件尚未落地；无 CHANGELOG / CONTRIBUTING，开源合规的第一印象会扣分。

    单人项目中

    测试集中在纯逻辑模块（选择是对的），UI / IO 层覆盖薄；关键人依赖明显。

    把「能干活」和「敢签字」放进同一个页面

    克隆下来 npm start 就能跑；把 renderer/ 当静态站点部署，也能得到一个完整工作台。上面那个 Demo 用的就是它的真实模块。
